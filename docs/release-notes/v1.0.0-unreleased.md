# CodePilot1C 1.0.0 — не выпущено

**Статус:** версия не выпущена и не опубликована.

## Несовместимая граница OSGi API

Версия 1.0.0 устанавливает намеренную несовместимую границу публичного OSGi API. Удалённая compatibility surface включает:

- `ProviderContextResolver`;
- API backend-оптимизаций в `ProviderCapabilities` и `ProviderUtils`;
- provider state в `ToolSurfaceContext`;
- прежний contributor с backend-ориентированным именем.

Внешние overlay bundles должны быть мигрированы и повторно скомпилированы против API 1.0.0. Compatibility shims для удалённых API не предоставляются.

При этом сохранены generic OpenAI-compatible transport и content fallback, а также внешние Qwen eval/runner assets.

Update site в рамках этой задачи не публиковался.

## Учётные данные инфобазы больше не выдаются модели

`get_infobase_credentials` больше не возвращает сохранённый пароль. Это намеренно несовместимое
изменение payload для внешних потребителей: вместо поля `password` инструмент сообщает
`password_available`, детерминированные `password_delivery`/`password_delivery_reason` и
`login_strategy`. Значения `/P`, а также содержащие `Pwd=` или `Password=` значения
`/IBConnectionString` в `additional_parameters` заменяются на `<redacted>`.

Инструменты с тегом `sensitive` больше не входят в wildcard (`*`) MCP Host; для экспозиции требуется
явно указать имя инструмента. Даже при явной экспозиции plaintext-пароль не возвращается. Содержимое и
текст ошибок результатов sensitive-инструментов не записываются в `~/.vibe/tool_calls.log` и trace:
сохраняются только тип результата, статус, длительность и длина пропущенного содержимого.

Автоматический вход сохранённым паролем пока недоступен. Поддерживаемые варианты — OS-аутентификация
или ручной вход самим пользователем непосредственно в открытой browser session; пароль нельзя просить
ввести в чат или передавать модели. Возврат безопасной автоматизации отложен до
`M4-TRUSTED-CREDENTIAL-CONSUMER`, где потребуется явный контракт доверия с конкретным потребителем.
Даже стратегия `no_password_required` намеренно не запускает автоматический вход: в текущей границе
разрешены только OS-аутентификация и ручной вход пользователя в browser session.

Это изменение не является общей санацией model-facing error envelope: текст исключения при ошибке
получения настроек доступа пока возвращается как раньше и требует отдельного security hardening.
