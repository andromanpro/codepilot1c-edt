# EDT 2026.2.2 и выборочный перенос идей EDT-MCP

Дата проверки: **31 октября 2026 года**. Это решение по подготовке перехода и составу текущего выпуска; новый EDT пока не установлен и не объявлен совместимым.

## Стоит ли обновлять EDT

**Стоит готовить переход на 2026.2.2 через отдельный стенд.** Польза для наших сценариев есть, но перенос рабочей области без проверки плагинов преждевременен.

Официальный стабильный выпуск [2026.2.2 вышел 23 октября](https://edt.1c.ru/blog/1c-edt-2026-2-vyshla/). В [описании 2026.2](https://v8.1c.ru/platforma/news/novoe-v-1c-edt-2026-2/) для нас существенны исправления фантомных изменений форм в расширениях, импорта из ИБ, обновлений расширений и сообщения об ошибках CLI-экспорта. Это заявленные изменения поставщика; собственных замеров скорости и совместимости с форком пока нет.

Платформа среды изменилась: Eclipse 2025-12 и Java 25. Для линии 1С 8.3.27 требуется **2202 или новее**; требования к другим линиям, по сообщению поставщика, не изменились. Установленная 8.3.27.1989 этому условию не соответствует; на рабочем компьютере есть также 8.5.1.1236 и 8.5.4.1306. Нельзя делать вывод по списку установок: надо проверить платформу каждого профиля запуска и допустимую версию для конкретной базы.

Порядок перехода:

1. Установить 2026.2.2 параллельно с прежней EDT; отдельная рабочая область и копии проектов. Сохранить прежние ZIP плагинов и версии расширений.
2. Проверить Java 25 и совместимость CodePilot, Git Flow и остальных используемых плагинов. Выпуск форка из этого релиза заявляет только EDT 2025.2.3 / Java 17.
3. Прогнать импорт/экспорт, формы и СКД, регистрацию базы, контексты расширений и `edt_update_extension`. Проверять независимое чтение результата, журнал EDT и конечный статус фоновой операции.
4. Проверить модульные тесты конфигурации, вызовы через MCP и сценарии Git Flow. Для объединения настроек учитывать замену XML на ZIP в новой EDT.
5. Переносить основной стенд после успешной проверки; простой запуск EDT и зелёная компиляция плагина этого не доказывают.

## Граница выбранного изменения

Новый вызов: `discover_tools {"tool_name":"mutate_form_model"}`. Старый вызов `{"category":"forms"}` сохраняется. Для справки возвращается один контракт из действующего model-facing реестра, включая обработку contributor-ов, без вызова инструмента и без изменения раскрытых категорий. Неверное имя, пустой параметр и неоднозначный запрос отклоняются. Протокол подтверждения и `validation_token` целевого инструмента сохраняется.

Это самостоятельная реализация идеи; исходный Java-код EDT-MCP не скопирован. Проверки и статус артефакта — в [описании выпуска](../release-notes/fork-2026-10-31.md).
